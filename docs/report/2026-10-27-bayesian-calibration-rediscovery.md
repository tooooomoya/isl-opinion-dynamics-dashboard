## Repost modularity

`docs/report/2026-07-17-stage2-target-correction.md` records the correction from an erroneous 0.75 target to 0.48. Conover et al. (2011), §3.1, reports retweet-community modularity 0.48 and mention-community modularity 0.17:
https://www.cse.cuhk.edu.hk/~cslui/CMSC5734/Conover_PoliticalPolarizationTwitter.pdf

The current `Analysis.computeSignModularityFromMatrix` computes directed, repost-count-weighted modularity for an opinion-sign partition, excluding target agents and the configured neutral band. This differs from the paper's detected-community partition and graph construction. Treat 0.48 as a provisional reference, not an exact matched estimand. Cross-camp reshare fraction should also be reported.

## Suggested next experiment

1. Resolve whether empirical counts include retweets. Keep original and reshare rates separate in model diagnostics until resolved. Compare per-person rates and total-volume shares separately.
2. Use a new launcher around the current model. Candidate parameter families: identity/recognition reward ratio, post/reshare/rewire costs, recognition saturation, exploration, post lifetime, reaction-distance preference. Choose a modest initial subset and explicit bounds. Keep feed treatment and initial-network conditions visible rather than letting the optimizer quietly select them away.
3. Start with a space-filling pilot and 3–5 seeds per point; adapt the simulator budget to measured runtime/noise. Use fresh seeds to validate several good candidates. Old observations are not valid warm starts after the mechanism change.
4. Retain separate objectives for bin-rate shape, activity heterogeneity (individual CSV supports bootstrap uncertainty), and network segregation. Inspect tradeoffs rather than hiding all mismatches in a single arbitrarily weighted score. Seven ordinal labels need not represent equal psychological distances; supplement Wasserstein with binwise residuals.
5. Seek a region of parameters that reproduces the pattern, not only a best point. A persistent behavior/network tradeoff would be evidence about the model's mechanisms, not a reason to keep enlarging the search indefinitely.
