# 2026-10-14 学習率と行動価値の揺れの比較

## 実験の目的と固定条件

ユーザーの k=20・rewire オフ・seed 0 の診断を受け、報酬定義を固定して学習率のみを変える。η=0.1 / 0.03 / 0.01、seed=0 / 1 / 2、各20,000 step、n=1000。既存の `bsc_k20` と同じ条件：状態なし bandit、w_fit=w_rec=20、q_init=40、τ=0.1、探索率は既定の0.05、HK、For You 100%、hop=5、β_F=10、ρ_L=ρ_R=0.3、dead_after=200、recognition は stock、fit は raw。

解析窓は step 15001–20000。共通 seed は初期条件を対応させるが、政策によって乱数消費が変わるためイベント単位の反実仮想比較ではない。η の変更は推定の揺れと環境変化への追従の両方を変える。

## 再現方法と検証

`python3 scripts/eta_noise_compare.py --parallel 9`。解析のみは `python3 scripts/eta_noise_compare.py --analyze`。標準ライブラリのみ使用。

`results/eta_noise_compare/source/` に現在の未コミット変更を含むJavaソースを凍結し、元ソースのSHA-256を `manifest.json` に保存。実験用コピーにだけ、個人別の報酬と選択直前のQの一次・二次モーメントを観測する処理を追加。乱数・効用・学習更新・行動選択は変更しない。既存の共有ビルドディレクトリや結果ディレクトリは使わない。完了済みrunは個別JSONで記録して再実行を避け、中断されたrunは再実行時に別ディレクトリへ退避する。

ModelTests と実行中の assertion を確認する。観測処理が挙動を変えないことは、同一seedの小規模runで元ソースと観測版の結果CSV・最終Q・行動数・TDログがバイト一致するかで検証する。

## 指標の定義と解釈の制限

- **Q差の時間的標準偏差**：各個人について、全３行動が利用可能な訪問時の POST−LIKE、RESHARE−LIKE、POST−RESHARE を記録。末尾5000 step全体の時間的標準偏差を求め、個人中央値でrunを要約する。環境変動やトレンドも含むため、純粋な推定ノイズとは呼ばない。
- **最大Qの交代率**：全３行動が利用可能な連続する観測訪問で、最大Qの行動が変わった割合。更新頻度・政策の変化の記述であり、正誤や最適性を示さない。
- **個人別政策のJSD**：末尾5000 stepの個人別行動頻度分布p_iについて H(mean_i p_i)−mean_i H(p_i)。自然対数を使用。有限標本や可用行動の違いを含み、正であることだけで役割分化の証拠としない。
- **500 step窓間の政策変化**：同じ個人の隣接窓の行動頻度分布の total variation distance（絶対差合計の半分）の中央値。標本誤差を含む。
- **個人内の報酬差**：同じ個人の行動別平均報酬を比較。各行動30更新以上の個人を対象とする。選択時の状況・履歴が一致していないため、因果的な行動効果ではない。
- **報酬分散の分解**：行動ごとの全報酬分散を、個人内分散の標本数加重平均と、個人別平均の標本数加重分散に分ける。集団の標準偏差を、そのまま一人のEMA学習の入力ノイズと解釈しない。個人内の標準偏差の中央値と個人間分散の寄与率を併記する。
- **初期値の残存**：最終Q表の最少行動回数nについて (1−η)^n > 0.05 となる個人の割合。stock bandit のEMA更新に対応する。低ηで初期値への依存が残っていないかを見る。
- **選択確率の検証**：末尾窓をQ差のbinごとに集計し、実選択率と理論確率との差の絶対値を提示回数で加重平均。観測処理自体の挙動一致も別に確認する。

ηを下げて政策が安定しても、最適な行動を学べたことにはならない。まず推定・選択の安定性を確認し、報酬の帰属や効用の変更とは区別する。

## 結果

９本すべて完了、全runでassertion error=0。以下は末尾5000 step、run単位の指標を３seedで平均したもの。個人中央値の指標は、各runで個人中央値を取ってからseed間で平均している。

観測処理の確認：n=100、step=1000、seed=0で、結果CSV・最終Q・行動数・TDログは元ソースとバイト一致。全３学習率のseed 0について、step=3000の個人別報酬集計を既存TDログと照合し、行動別更新数は完全一致、平均報酬はCSV丸め誤差内で一致した。凍結ソースのModelTestsはALL PASS。

### 検証と結論

Q差のbin別選択率と理論確率の提示数加重MAEは η=0.1 / 0.03 / 0.01 で0.00100 / 0.00084 / 0.00094。選択ロジックに大きな不一致はない。

結論：ηを下げるとQ差の時間的な揺れは減る。しかし、元診断の「集団の報酬ばらつきが各人の行動差を埋める」という説明は、個人間異質性と個人内ノイズを混同していた。個人内で観測される行動別平均報酬差自体が非常に小さい。学習率の変更は推定の安定化には有効だが、行動に帰属できる報酬信号の弱さを解決したとは言えない。

次の比較用の候補はη=0.03（順位と窓間政策の変動が小さく、初期値残存も少ない）。η=0.01はさらにQ差の揺れを抑える対照として残す。現在のモデルの既定値は変更していない。次の設計課題はstock報酬の持ち越しと行動への帰属であり、即時報酬への置換や時間差分への置換は効用改訂として別実験にする。

## 追加：ネットワーク位置に応じた役割分化（2026-10-14）

ユーザーの研究目標は、全員が一つの最良行動へ収束することではなく、ネットワーク上の位置に応じた役割分化が反映されること。この目標に合わせ、既存９本をフォロワー数（有向グラフの入次数）別に再集計した。再実行はしていない。

実行：`python3 scripts/eta_role_by_position.py`。行動割合は、末尾5000 stepの各個人の割合を層内で等重み平均し、その後３seedで平均。フォロワー数の区間を固定し、次数同率のノードを人工的に分割する分位階層は使わない。グラフの辺集合をソートしてハッシュを比較し、各seedについて全ηで同じグラフであることを確認した。LIKE/RESHAREでfollowee queueが並べ替えられるため、辺CSVの行順のハッシュはグラフ比較に使わない。ネットワーク位置には中心性・コミュニティ等もあるが、今回は入次数のみを扱う。

### 解釈の補足

フォロワー数に応じてRESHARE選択率が上がり、LIKE選択率が下がることが確認できる。η=0.1でも周辺層のRESHAREは35%程度、20–49と50+層は64–66%で、傾向はη=0.03固有ではない。η=0.01では高入次数層のRESHARE率が約46–50%に留まり、20,000 step時点の分化は弱い。

全体の個人内報酬差の中央値が小さいことは、全位置で行動利得差が小さいことを意味しない。人口の約63%を占める0–4人層では差がほぼゼロだが、5–19人層では差が大きい。前節の「個人内で観測される行動別平均報酬差自体が非常に小さい」は全体中央値の記述であり、位置別の一般命題として読んではならない。

現時点で言えるのは、位置に応じた行動割合の分化が観測され、一部の層では個人内の報酬差も対応していること。各人が自分にとって有利な役割を獲得したと断定するには、①学習なしの等Q政策との層別比較、②同じ個人・環境で行動のみを変更する反実仮想比較、③より長い窓での政策持続性を追加する必要がある。報酬差は状態・履歴の違いを含み、入次数だけによる因果的説明でもない。

研究上の主指標を、集団平均の行動優劣から、**位置別の行動配分・その持続性・同じ位置内の個人別利得への対応**へ移す。全員の行動差を大きくすることや、次数から行動を直接指定することは目標にしない。現在の周辺層は読む・支える役割に特化せずほぼ混合政策のため、周辺層まで役割分化を求めるなら、制作費用・消費満足・支援の見返り・報酬帰属の設計を段階的に検討する。
